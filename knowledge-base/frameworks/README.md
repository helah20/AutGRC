# قاعدة معرفة أطر الهيئة الوطنية للأمن السيبراني (NCA)

هذا المجلد هو نتيجة تحليل الملفات السبعة في مجلد **Frameworks** على Google Drive،
وتحويلها إلى بيانات منظمة جاهزة لأمرين:

1. **قاعدة المعرفة في n8n**: تسأل عن أي ضابط وتأتيك الإجابة من النص الرسمي مع رقم الضابط.
2. **تحسين موقع AutGRC**: ملفات جاهزة للاستيراد في الموقع، وتقرير بالفجوات والأخطاء الموجودة فيه حاليًا.

## ما الذي استُخرج؟

كل ضابط وضابط فرعي بنصه الكامل، مع النطاق الرئيسي والفرعي والهدف. الأعداد مطابقة
تمامًا لما تذكره كل وثيقة عن نفسها:

| الإطار | الإصدار | نطاقات فرعية | ضوابط رئيسية | ضوابط فرعية | بيانات إضافية |
| --- | --- | --- | --- | --- | --- |
| الضوابط الأساسية ECC | ECC-2:2024 | 28 ✓ | 108 ✓ | 92 ✓ | سجل التغييرات عن إصدار 2018 (31 تغييرًا) |
| الحوسبة السحابية CCC | CCC-2:2024 | 24 ✓ | 55 ✓ | 120 ✓ | لكل ضابط: مقدّم الخدمة (CSP) أو المستفيد (CST) |
| الأنظمة الحساسة CSCC | CSCC-1:2019 | 21 ✓ | 32 ✓ | 73 ✓ | |
| البيانات DCC | DCC-1:2022 | 11 ✓ | 19 ✓ | 47 ✓ | الانطباق حسب مستوى التصنيف (عام/سري/سري للغاية…) والتكرار |
| التقنية التشغيلية OTCC | OTCC-1:2022 | 23 ✓ | 47 ✓ | 122 ✓ | الانطباق حسب مستوى المنشأة L1 / L2 / L3 |
| العمل عن بعد TCC | TCC-1:2021 | 16 ✓ | 21 ✓ | 42 ✓ | |
| حسابات التواصل الاجتماعي OSMACC | OSMACC-1:2021 | 12 ✓ | 15 ✓ | 38 ✓ | |
| **المجموع** | | **135** | **297** | **534** | **831 ضابطًا** |

## الملفات

| المسار | الاستخدام |
| --- | --- |
| `markdown/*.md` | نص الأطر مرتبًا (ملف لكل إطار + ملف تغييرات ECC). **هذا ما يُرفع إلى n8n.** |
| `import/*.csv` | ملف لكل إطار بصيغة الاستيراد التي يقرؤها الموقع (`Reference, Title, Statement, Domain, Parent, Level`). |
| `data/nca-frameworks.json` | كل شيء في ملف واحد منظم (للمطورين). |
| `data/site-gap-report.json` | تفاصيل المقارنة مع الموقع (كل الأخطاء أدناه بالتفصيل). |
| `tools/` | سكربتات الاستخراج لإعادة التوليد عند صدور إصدار جديد. |

### تحميلها في قاعدة المعرفة (n8n)

بعد تشغيل قاعدة المعرفة (راجع `../README.md`):

```bash
cd knowledge-base
./scripts/ingest-folder.sh frameworks/markdown
```

جُرّب هذا فعليًا: رُفعت الملفات الثمانية وتحولت إلى 310 مقطعًا قابلًا للبحث.
بعدها تستطيع أن تسأل مثلًا: «ما متطلبات DCC لتحديث الأنظمة للبيانات السرية؟»
أو «ما الذي تغيّر في ECC 2024 عن 2018؟».

### استيرادها في الموقع

الموقع يدعم هذا مسبقًا (`server/src/services/import-framework.js`).
اختُبرت الملفات السبعة بنفس كود الموقع: **991 صفًا مقبولًا، 0 مرفوض**، وكل نطاق
فرعي وضابط رُبط تلقائيًا بأحد نطاقات الموقع الـ24.

- لـ ECC و CCC: سجّل أولًا **إصدارًا جديدًا** (Edition) عبر `POST /api/frameworks/editions`
  حتى يبقى إصدار 2018/2020 قائمًا لمن تقيّم عليه، ثم استورد الملف.
- لـ CSCC و DCC و TCC: استورد مباشرة على الإطار الموجود. لن يُحذف شيء، وستُصحَّح العناوين.
- OTCC و OSMACC: أضف الإطارين أولًا ثم استورد.

| المشكلة | الحالة |
| --- | --- |
| عناوين نطاقات CSCC و DCC و TCC و CCC لا تطابق الوثائق (البند 3) | ✅ **أُصلحت**: العناوين والترقيم الآن كما في الوثائق حرفيًا (`server/src/knowledge/frameworks.js`) |
| مراجع غير موجودة في هذه الأطر الأربعة (البند 4) | ✅ **أُصلحت**: حُذفت أو وُجّهت إلى القسم الصحيح |
| مراجع بقيت أرقامها لكن تغيّر معناها (مثل DCC 2-3 كانت «صلاحيات الوصول» وهي فعليًا «الأجهزة المحمولة») | ✅ **أُصلحت**: 56 متطلبًا أُعيد توجيه مراجعها حسب موضوعها |
| متطلبات الاستمرارية والتعافي تستشهد بـ ECC 2-13 (إدارة الحوادث) | ✅ **أُصلحت** ← ECC 3-1 (الاستمرارية) |
| متطلبات السحابة تستشهد بـ ECC 4-1 (الأطراف الخارجية) | ✅ **أُصلحت** ← ECC 4-2 (الحوسبة السحابية والاستضافة) |
| أقسام حقيقية لم يغطّها أي متطلب (23 قسمًا) | ✅ **أُصلحت**: رُبطت بالمتطلب المطابق لموضوعها (19 متطلبًا) |
| CCC على إصدار 2020 | ✅ **رُفع إلى CCC-2:2024** (الإصدار الموجود في ملفاتك) |
| ECC على إصدار 2018 ونطاقه الخامس | ✅ **رُفع إلى ECC-2:2024**: الترقيم والعناوين من الوثيقة، والمراجع المنقولة وُجّهت حسب معناها (مثلًا 1-3-3 «المراجعة» صارت 1-3-4)، وأُزيل النطاق 5 |
| متطلبات تستشهد بـ ECC 2-7-3 المحذوف (4 متطلبات) | ✅ وُجّهت إلى 2-7-2 (التصنيف) أو 2-7-1 |
| ربط متقاطع (crosswalk) يشير إلى أرقام تغيّر معناها (3 روابط) | ✅ حُذفت، فلا يوجد في الوثائق قسم مقابل لها |
| 25 متطلبًا تستشهد بضوابط عُدّلت صياغتها في 2024 (مثل 2-2-3-2 التحقق المتعدد، 2-8-3 التشفير) | ⏳ المراجع صحيحة، لكن نص السياسة المولّدة يحتاج مراجعة بشرية مقابل الصياغة الجديدة (القائمة في `data/site-gap-report.json`) |
| متطلب أنظمة التحكم الصناعي فقد مرجع ECC 5-1 | ✅ يستشهد الآن بـ OTCC (الفصل، التغيير، المخاطر، الأصول، حماية الأنظمة، المراقبة) |
| OTCC و OSMACC غير موجودين | ✅ **أُضيفا** بنطاقاتهما وأقسامهما كما في الوثيقتين، وكل قسم مربوط بالمتطلب المطابق لموضوعه |
| حقل الانطباق (مستوى التصنيف / المنشأة / CSP-CST) | ✅ **أُضيف**: يُستورد مع ملفات `import/`، ويُقيَّم مقابل ملف المنظمة (مستويات التصنيف، مستوى منشأة OT، دور السحابة)، ويظهر في بيان القابلية للتطبيق وتصديره |

جميع اختبارات الموقع تنجح (115)، ومدقق قاعدة المعرفة لا يجد أي مرجع مكسور. التقرير `data/site-gap-report.json` لم يعد يجد أي مرجع أو عنوان مخالف للوثائق في الأطر السبعة.

> **ملاحظة لمن عنده نسخة تعمل من الموقع:** قاعدة البيانات الموجودة لن تتحدث تلقائيًا، لأن
> التهيئة (seed) تضيف ولا تعدّل. للتحديث: إما `npm run reset` (يمسح البيانات التجريبية ويعيد
> إنشاءها)، أو استيراد ملفات `import/`، وهو يحدّث العناوين دون حذف شيء. ولمن يريد الإبقاء على
> ECC-1:2018 لتقييم قائم: سجّل ECC-2:2024 كإصدار جديد (`POST /api/frameworks/editions`) ثم استورد ملفه.

### 6. الأطر الأخرى ما زالت تستشهد بترقيم ECC-2018

CCC و CSCC و DCC و TCC و OSMACC و OTCC تستشهد بترقيم ECC-1:2018. من 166 إحالة إلى ECC فيها:
- **9 إحالات إلى ضوابط حُذفت** في 2024. أكثرها «ECC 2-7-3»، وتظهر في الأطر الستة كلها.
- **10 إحالات إلى ضوابط أو أهداف عُدّلت**.
- إحالة واحدة إلى رقم لم يعد موجودًا (OTCC 2-6-2 ← ECC 2-7-4).

لذلك يحتاج الموقع إلى **جدول ربط 2018 ← 2024** حتى لا تنكسر هذه الإحالات عند الترقية.

### 7. بيانات «الانطباق» غير موجودة في الموقع

ثلاثة أطر تحدد على **من** و**متى** ينطبق كل ضابط، والموقع لا يملك حقلًا لذلك:
- **DCC**: لكل ضابط مستويات التصنيف التي ينطبق عليها، وأحيانًا تكرار مختلف لكل مستوى.
  مثال 2-2-1-1: تحديثات الأمان «شهريًا على الأقل» للعام والسري، و«فورًا» للسري جدًا وسري للغاية.
- **OTCC**: لكل ضابط مستوى المنشأة L1 أو L2 أو L3.
- **CCC**: لكل ضابط هل هو على مقدّم الخدمة (CSP) أم المستفيد (CST).

إضافة هذا الحقل تجعل الموقع يولّد سياسات مخصصة لتصنيف بيانات الجهة أو مستوى منشأتها،
وهذه ميزة تنافسية حقيقية.

## التوصيات مرتبة بالأولوية

1. **تصحيح عناوين النطاقات والمراجع الخاطئة** (البندان 3 و 4). هذه أخطاء ظاهرة لأي مدقق،
   والإصلاح سهل: استيراد ملفات `import/` يصحح العناوين، ثم تُعدَّل مراجع `req-*.js` المذكورة.
2. **إضافة ECC-2:2024 و CCC-2:2024 كإصدارات جديدة**، ونقل `ics_ot_protection` إلى OTCC،
   وإعادة ربط المتطلبات الأربعة المرتبطة بـ ECC 2-7-3 المحذوف.
3. **إضافة OTCC و OSMACC** إلى قائمة الأطر.
4. **إضافة حقل الانطباق** (مستوى التصنيف / مستوى المنشأة / CSP-CST) إلى `framework_requirements`.
5. **جدول ربط ECC 2018 ← 2024** لتحويل الإحالات تلقائيًا.

## ملاحظات على دقة البيانات

- النصوص منقولة حرفيًا من ملفات PDF الإنجليزية. النسخة العربية هي الملزمة قانونيًا حسب إخلاء المسؤولية في كل وثيقة.
- **DCC** نصّه في PDF غير قابل للنسخ (خطوط بلا ترميز)، فاستُخرج بالتعرف الضوئي (OCR).
  الأعداد مطابقة، ومستويات الانطباق ذات التكرار نُقلت يدويًا من صور الصفحات.
  يُستحسن مراجعة سريعة للنصوص قبل الاعتماد عليها في التدقيق.
- **OTCC**: الوثيقة نفسها تكرر عنوان 1-7 للنطاق 1-8، فاعتُمد العنوان الوارد في مخطط النطاقات
  («Cybersecurity Awareness and Training Program»).
- **OTCC**: إجمالي الضوابط حسب المستوى بعد الاستخراج هو L1=150، L2=120، L3=60، والوثيقة
  تذكر 151 و 117 و 56. تحققنا من التوزيع بطريقتين مستقلتين وتطابقتا، ومراجعة الصفحات بصريًا
  أكدت صحة العينة، فالفرق على الأرجح في طريقة عدّ الوثيقة نفسها.
