# مقارنة عينات السياسات بما يولّده الموقع

**المصدر:** مجلد Drive «ISO27001-Policies and Procedures and Forms and Templates»، وفيه 786 ملفاً.

**ما لم يُرفع إلى المستودع:** لا نص من القوالب أو الأدلة التجارية. هذا الملف يذكر العناوين والبنية فقط.

**ما استُبعد من التحليل:** الملفات الشخصية، مثل الفواتير ونتائج الاختبارات والشهادات.

## 1. البنية: قوالب الهيئة مقابل وثائق الموقع

قرأتُ ثلاثة قوالب إنجليزية رسمية من الهيئة:
- سياسة إدارة الهويات والصلاحيات.
- معيار أمن الشبكات.
- إجراء إدارة الثغرات.

بنية القوالب الثلاثة واحدة:

| قسم القالب | في الموقع |
|---|---|
| إخلاء مسؤولية الهيئة | لا يلزم، فالقالب «مثال توضيحي» والموقع يولّد وثيقة المنشأة نفسها |
| جدول اعتماد الوثيقة (التوقيع، التاريخ، الاسم، المسمى، الدور) | موجود في تصدير Word (`export-docx.js`): قسم «الاعتماد» من سجل الموافقات |
| جدول ضبط الإصدارات | موجود: «سجل الإصدارات» |
| جدول المراجعة (دورية المراجعة، آخر مراجعة، المراجعة القادمة) | موجود: دورية المراجعة، وتاريخ آخر مراجعة (من آخر اعتماد أو نشر)، وتاريخ المراجعة القادمة |
| الغرض والنطاق | موجود |
| بنود السياسة، مجمّعة تحت عناوين فرعية | موجود: «بنود السياسة»، وكل بند يحيل إلى مراجعه |
| الأدوار: المالك، المراجعة والتحديث، التنفيذ، قياس الالتزام | موجود في «الأدوار والمسؤوليات»، وجدول الأدوار الأربعة في قسم «الحوكمة» بالسياسة |
| التحديث والمراجعة: سنوياً على الأقل أو عند تغيّر التشريعات | موجود: قسم «المراجعة» |
| الالتزام وعواقب المخالفة | موجود: «الالتزام» و«الإنفاذ» |
| الإجراء: مراحل، وجدول خطوات (رقم، خطوة، وصف، المسؤول، المدخلات، المخرجات، أصحاب العلاقة) | موجود وأوسع: خطوات تفصيلية، ومخطط سباحة، ونقاط قرار، وتصعيد، ومؤشرات أداء |

**الخلاصة:** وثائق الموقع تحوي كل أقسام قالب الهيئة وتزيد عليها، مثل الاستثناءات والقياس والمراجع وإحالة كل بند إلى مصدره.

**الفرقان الصغيران أُغلقا:** صار جدول بيانات الوثيقة يعرض دورية المراجعة وتاريخ آخر مراجعة، وصارت السياسة تعرض الأدوار الأربعة كما في قوالب الهيئة.

## 2. المحتوى: بنود سياسة الهويات

قارنتُ بنود قالب الهيئة بمتطلبات المجال `iam` في الموقع وبالمعايير التقنية في `req-access.js` و`req-tech.js`. الموقع يغطي كل البنود تقريباً، ومنها:
- منع الحسابات العامة.
- مصفوفة الصلاحيات (الحاجة للمعرفة، فصل المهام، أقل الصلاحيات).
- مهلة الجلسة والإقفال.
- الحسابات الخاملة وحسابات الخدمة.
- المصادقة متعددة العناصر للصلاحيات الهامة.
- منع الوصول المباشر لقواعد البيانات.
- سجل كلمات المرور.
- الحسابات الافتراضية.
- منع تعدد الجلسات.

**بندان في القالب لا مقابل لهما في الموقع:**
- تغيير سلاسل مجتمع SNMP الافتراضية.
- اصطلاح موحّد لتسمية معرّفات المستخدمين.

## 3. الموضوعات: قوالب الهيئة الرسمية مقابل مجالات الموقع

في المجلد 33 سياسة و37 معياراً و5 إجراءات من قوالب الهيئة، باللغتين العربية والإنجليزية. الموقع فيه 24 مجالاً، وكل مجال يولّد سياسة ومعياراً وإجراءً.

### مغطاة: لها مجال أو متطلبات واضحة
- إدارة الأصول والاستخدام المقبول.
- النسخ الاحتياطي.
- التشفير وإدارة المفاتيح.
- سجلات الأحداث والمراقبة.
- الحوادث.
- الهويات والصلاحيات.
- أمن الشبكات واللاسلكي والوكيل.
- الثغرات والتحديثات واختبار الاختراق.
- الأمن المادي.
- إدارة المخاطر.
- التطوير الآمن والبرمجة الآمنة.
- الأطراف الخارجية.
- الحوسبة السحابية.
- استمرارية الأعمال.
- الإعدادات والتحصين.
- الحماية من البرمجيات الضارة.
- الأجهزة المحمولة وBYOD.
- وسائط التخزين.
- حماية البيانات ومنع التسرب والخصوصية.
- الموارد البشرية، ضمن التوعية.
- الالتزام والمراجعة، ضمن الحوكمة.

### الفجوات: موضوعات لها قالب مستقل عند الهيئة وليس لها مجال في الموقع

| الموضوع | المرجع | الوضع في الموقع | الاقتراح |
|---|---|---|---|
| **أمن البريد الإلكتروني** | ECC 2-4، وهو مجال فرعي كامل | بند واحد هو `network_security.email_security` | مجال مستقل أو بنود إضافية: التصفية، المصادقة المتعددة لـ webmail، الأرشفة، DMARC/SPF/DKIM، الحماية من APT |
| **أمن قواعد البيانات** | سياسة ومعيار عند الهيئة؛ ECC 2-3 | غير موجود كموضوع | مجال `database_security` أو بنود ضمن `endpoint_security` |
| **أمن الخوادم والمحاكاة الافتراضية** | معايير الهيئة؛ ECC 2-3 | التحصين عام ولا يميّز الخوادم أو المضيف الافتراضي | بنود خاصة بالخوادم وطبقة المحاكاة الافتراضية |
| **حسابات التواصل الاجتماعي** | OSMACC بأكمله، ومعيار عند الهيئة | الإطار مُضاف والإحالة إلى متطلبات عامة فقط | مجال `social_media` يغطي ملكية الحسابات وكلمات المرور والصلاحيات والتطبيقات المرتبطة |
| **أنظمة التحكم الصناعي OT/ICS** | OTCC بأكمله، وسياسة ومعيار عند الهيئة | بند واحد هو `ics_ot_protection` | مجال `ot_security`. النطاق كبير: 23 مجالاً فرعياً، ومستويات المنشأة L1–L3 |
| **الحماية من DDoS وAPT وEDR/NDR** | معايير الهيئة | مذكورة ضمن بنود أعم | تكفي إضافة بنود معيار تقني |

### إجراءات عند الهيئة لا مقابل لها
- **إجراء تطوير وثائق الأمن السيبراني:** كيف تُكتب الوثيقة وتُراجَع وتُعتمد. الموقع يطبّق دورة الحياة هذه في سير العمل، ولا يولّدها وثيقةً مكتوبة.
- **إجراء إتلاف المعلومات والوسائط والمعدات.**
- **إجراء التدقيق.**

## 4. النماذج والسجلات: ما ينقص الموقع

الموقع اليوم يولّد ثمانية أنواع من الوثائق:
- سياسة.
- معيار.
- إجراء.
- دليل.
- أدوار.
- مصفوفة RACI.
- مصفوفة ضوابط.
- إطار ضوابط.

وفيه سجلات حيّة:
- المخاطر ومعالجتها.
- بيان التطبيق (SoA).
- الملاحظات.
- الأدلة.
- الفجوات.

وفيه تقارير: التغطية، والجاهزية للتدقيق، وحالة المراجعات.

**نماذج في المجلد ليس لها مقابل:**

| النموذج | المرجع | الأولوية |
|---|---|---|
| خطة التدقيق الداخلي وجدوله، وتقريره، وقائمة الفحص | ISO 9.2؛ ECC 1-8 | **أُضيف** تقرير «Internal Audit Plan»: برنامج مبني على المخاطر مع معايير التدقيق وسبب كل أولوية. تقرير التدقيق نفسه ما زال ناقصاً |
| جدول أعمال مراجعة الإدارة ومحضرها | ISO 9.3؛ ECC 1-2-3 (اللجنة الإشرافية) | **أُضيف** تقرير «Management Review Inputs» بكل مدخلات 9.3.2. محضر القرارات ما زال ناقصاً |
| **وثيقة تنظيم اللجنة الإشرافية للأمن السيبراني** | قالب رسمي من الهيئة؛ ECC 1-2-3 | عالية |
| **الاستراتيجية وخارطة الطريق** | قالب رسمي من الهيئة؛ ECC 1-1 | عالية: المتطلب `cyber_strategy` يولّد بند سياسة، لا وثيقة استراتيجية |
| **الهيكل التنظيمي للأمن السيبراني** | قالب رسمي من الهيئة؛ ECC 1-2 و1-4 | متوسطة: الأدوار موجودة والهيكل غير موجود |
| سجل عدم المطابقة والإجراءات التصحيحية (CAPA) | ISO 10.2 | منخفضة: سجل «الإجراءات التصحيحية» موجود، والتحقق فيه يقوم به شخص غير المنفّذ. ينقصه حقل للسبب الجذري فقط |
| تحليل أثر الأعمال (BIA) | ISO 22301؛ ECC 3-1 | متوسطة: `business_continuity.bia` متطلب وليس نموذجاً |
| أهداف أمن المعلومات وخطتها | ISO 6.2 | متوسطة |
| سجل جهات الاتصال بالسلطات ومجموعات الاهتمام | ISO A.5.5 وA.5.6 | منخفضة |
| تعهد الالتزام بالسياسات واتفاقية السرية | قالبان رسميان من الهيئة؛ ECC 1-9-3-1 | منخفضة: نموذجان قصيران |
| قوائم فحص الأمن في المشاريع وإدارة التغيير، وفي تطوير البرمجيات | قالبان رسميان من الهيئة؛ ECC 1-6 | متوسطة |
| مؤشرات أداء الأمن السيبراني (KPI) | ملفات KPI في المجلد | منخفضة: المؤشرات موجودة داخل الوثائق، وينقصها لوحة مستقلة |
| خطط الاستجابة لسيناريوهات محددة (فدية، حجب خدمة، تسرب بيانات) | ISO A.5.24 | منخفضة |

## 5. قاعدة المعرفة

السكربت `scripts/convert-samples.py` يحوّل مجلد العينات من جهازك إلى Markdown داخل `documents/samples/`. هذا المجلد مستثنى من git.
- **ما يحوّله:** docx وxlsx وpdf النصية.
- **ما يتخطاه:** ملفات pdf الممسوحة ضوئياً، والملفات الشخصية بحسب الاسم. يمكن إضافة أنماط استثناء أخرى بـ `--skip`.
- **ما يطبعه:** قائمة بكل ملف تخطّاه مع السبب.

```bash
pip install python-docx openpyxl pdfplumber
python3 scripts/convert-samples.py "~/Downloads/ISO27001-Policies and Procedures and Forms and Templates"
./scripts/ingest-folder.sh documents/samples
```

**ملاحظة:** في المجلد ملفات أعدّها مستشارون لعملاء محددين، وفيها أسماء تلك الجهات. هي مفيدة كمرجع في قاعدة معرفتك المحلية. لا يُنقل منها شيء إلى الموقع.
